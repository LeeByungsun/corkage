# Store Card Visit Decision Design

작성일: 2026-05-29

## 목적

`/store` 목록 카드는 사용자가 동탄구에서 콜키지 가능 매장을 빠르게 고르는 화면이다.
카드 하나를 보고 아래 네 가지를 바로 판단할 수 있어야 한다.

1. 이 매장은 콜키지가 가능한가
2. 무료인지, 유료인지, 비용 확인이 필요한지
3. 방문 전 확인해야 할 조건이 있는가
4. 상세 화면으로 들어갈 가치가 있는가

## 현재 문제

현재 카드는 정보는 충분하지만 우선순위가 약하다.

- `낮은 신뢰`, `최신 기준 안` 같은 보조 정보가 먼저 눈에 들어온다.
- `콜키지 가능 (무료)` 또는 `콜키지 가능 (유료)`가 조건과 태그로 중복 표시된다.
- 주소가 길어 카드 높이가 커진다.
- `상세 보기` 버튼의 행동 유도가 약하다.

## 선택한 방향

방문 결정형 카드로 정한다.

핵심 판단 정보는 위로 올리고, 신뢰/출처/확인일은 아래 보조 문구로 낮춘다.
카드는 예쁜 홍보 카드보다 빠른 판단 카드에 가깝게 만든다.

## 카드 정보 우선순위

1. 지역/카테고리
2. 식당명
3. `가능` 상태 배지
4. 비용 요약
5. 조건 한 줄
6. 주소 한 줄
7. 확인일/출처/신뢰도 보조 문구
8. 상세 보기 버튼

## 표시 구조

예시:

```text
동탄구 목동 · 양식                         가능

곧 동탄 본점

유료 · 비용 확인 필요
콜키지 가능 (유료)

왕배산3길 6 · 2026-05-28 확인
공개 웹 참고 · 방문 전 조건 확인 권장

[상세 보기]
```

무료 매장 예시:

```text
동탄구 목동 · 양식                         가능

예시 매장

무료 · 조건 확인 필요
콜키지 가능 (무료)

왕배산3길 6 · 2026-05-28 확인
공개 웹 참고 · 방문 전 조건 확인 권장

[상세 보기]
```

## 비용 표시 규칙

`available` 매장 기준으로 아래처럼 표시한다.

- `feeUnit === 'free'`
  - `무료 · 조건 확인 필요`
- `corkageFee`가 숫자이고 `feeUnit`이 병당/테이블당인 경우
  - 기존 금액 라벨을 유지하되 뒤에 조건 확인 의미가 드러나야 한다.
  - 예: `30,000원 / 병 · 조건 확인 필요`
- 유료 태그는 있으나 금액이 없는 경우
  - `유료 · 비용 확인 필요`
- 무료/유료 판단이 없고 가능만 확인된 경우
  - `비용 확인 필요`

무료도 반드시 조건 확인 문구를 포함한다.
콜키지는 무료라도 병 수, 주종, 예약, 잔 세팅 조건이 있을 수 있기 때문이다.

## 조건/태그 중복 제거

`conditionNote`와 `rawFacilities`의 콜키지 태그가 같은 문구이면 한 번만 표시한다.

예:

- `conditionNote = 콜키지 가능 (유료)`
- `rawFacilities = [콜키지 가능 (유료)]`

이 경우 조건 영역에만 표시하고 태그 반복은 숨긴다.

서로 다른 정보라면 둘 다 표시할 수 있다.
예를 들어 조건은 `예약 시 가능`, 태그는 `콜키지 가능 (무료)`이면 둘 다 의미가 다르므로 유지한다.

## 주소 표시 규칙

카드에서는 전체 주소보다 방문 판단에 필요한 짧은 주소를 우선한다.

- `경기도 화성시 동탄구` 접두어는 목록 카드에서 생략 가능하다.
- 도로명과 건물번호 중심으로 보여준다.
- 너무 긴 건물명/층/호수는 한 줄 또는 두 줄에서 줄임 처리한다.
- 상세 페이지와 지도 영역에서는 기존처럼 보정된 전체 주소를 유지한다.

예:

- 카드: `왕배산3길 6`
- 상세/지도: `경기도 화성시 동탄구 왕배산3길 6 1층`

## 출처/신뢰도 표시 규칙

신뢰도 배지는 카드 상단의 핵심 정보로 두지 않는다.
아래 보조 문구로 합친다.

예:

```text
공개 웹 참고 · 2026-05-28 확인 · 방문 전 조건 확인 권장
```

운영자 검수 또는 매장 직접 확인이면 아래처럼 더 짧게 표시한다.

```text
매장 확인 · 2026-05-28 확인
```

## 버튼 규칙

카드 하단의 기본 CTA는 유지한다.

- 문구: `상세 보기`
- 역할: 조건, 주소, 지도 확인으로 이어지는 명확한 진입점
- 시각적으로 현재보다 더 강한 버튼으로 보이게 한다.

## 구현 범위

포함:

- `/store` 목록 카드 레이아웃
- 카드 내 비용/조건/주소/출처 문구 정리
- 중복 콜키지 태그 제거
- 기존 상세 보기 링크 유지
- 관련 컴포넌트 테스트 갱신

제외:

- 상세 페이지 전체 리디자인
- 지도 UI 변경
- DB 구조 변경
- 콜키지 데이터 정책 변경
- 지역 선택 UI 변경

## 테스트 기준

- 카드 상단에서 식당명과 `가능` 배지가 보인다.
- 무료 매장은 `무료 · 조건 확인 필요`를 표시한다.
- 유료 금액 미상 매장은 `유료 · 비용 확인 필요`를 표시한다.
- 조건 문구와 콜키지 태그가 같은 경우 중복 표시하지 않는다.
- 카드 주소는 짧게 표시된다.
- 상세 보기 링크는 기존 경로를 유지한다.
- 기존 `/store` 카드 테스트와 빌드 검증이 통과한다.

## 리뷰 체크

- 이 스펙에는 미정 항목이 없다.
- 구현 범위는 목록 카드로 제한된다.
- 무료도 조건 확인이 필요하다는 정책이 명시되어 있다.
- 상세 페이지/지도/DB 변경은 범위에서 제외되어 있다.
