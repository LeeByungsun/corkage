# Naver Local Search API Checklist

## 목표

이 문서는 네이버 지역 검색 API가 `콜키지 식당 후보 수집`에 실제로 쓸 만한지 확인하기 위한 체크리스트입니다.

현재 단계에서는 지도를 붙이지 않습니다.

먼저 아래만 검증합니다.

1. 식당 후보 목록이 잘 나오는가
2. 응답 필드가 충분한가
3. 검색어 품질이 괜찮은가
4. 제품에서 저장/표시해도 되는 정책 경계가 무엇인가

## 이번 단계 완료 기준

아래가 확인되면 다음 단계로 넘어갑니다.

- [ ] 검색어 5~10개 기준으로 결과가 안정적으로 나온다
- [ ] `title`, `category`, `address`, `roadAddress`, `mapx`, `mapy`가 실제 응답에 들어온다
- [ ] 식당 후보가 아닌 노이즈 비율을 대략 판단할 수 있다
- [ ] 콜키지 관련 키워드가 유효한지 판단할 수 있다
- [ ] 영속 저장/상업적 사용/재배포 경계를 분리해서 기록할 수 있다

## 사전 준비

- [ ] 네이버 개발자 센터에서 애플리케이션 생성
- [ ] 검색 API 사용 설정 확인
- [ ] `Client ID` 확보
- [ ] `Client Secret` 확보
- [ ] Vercel 또는 로컬 서버 환경변수 위치 결정
- [ ] 테스트 호출은 프론트가 아니라 서버 경유로 한다는 점 확인

## 공식 기준으로 먼저 알고 갈 것

- 엔드포인트: `https://openapi.naver.com/v1/search/local.json`
- 메서드: `GET`
- 인증: `X-Naver-Client-Id`, `X-Naver-Client-Secret`
- 공식 핵심 필드: `title`, `category`, `description`, `address`, `roadAddress`, `mapx`, `mapy`
- 하루 호출 한도: 25,000회
- `telephone`은 공식 문서상 값을 반환하지 않는 필드
- `link`는 상세 정보 URL로 설명되지만 예시 응답에서 비어 있음
- 지역 검색 결과 이후 `상세 정보 전용 공식 API`는 현재 문서에서 확인되지 않음
- 네이버 API 서비스 이용약관(2025-05-27 개정)에는 `네이버 지역정보를 수집하여 별도 데이터베이스로 관리하며 이용하는 행위` 금지 문구가 있음
- 같은 약관에는 회사의 사전 승인 없이 `스크립트, 매크로, 봇, 크롤러` 등 자동화 수단으로 주기적/반복적으로 접근하는 행위 금지 문구가 있음
- 네이버 개발자 FAQ에는 `검색결과를 보여주는 서비스` 또는 `네이버와 유사한 검색서비스`의 경우 상업적 목적 사용 제한 안내가 있음
- `map.naver.com/robots.txt`도 현재 크롤링 친화적 상태가 아님

## 1. 기본 호출 확인

### 체크

- [ ] 서버에서 1회 호출 성공
- [ ] 200 응답 확인
- [ ] JSON 파싱 성공
- [ ] `items` 배열 존재 확인
- [ ] 검색 결과 1개 이상 확인

### 추천 첫 검색어

- `강남 와인바`

### 기록할 것

- 실제 요청 파라미터
- 응답 상태 코드
- 응답 총 개수
- 첫 3개 결과 요약
- 오류가 났으면 오류 코드와 메시지

## 2. 검색어 품질 확인

아래 검색어를 하나씩 테스트합니다.

- [ ] `강남 와인바`
- [ ] `성수 이탈리안`
- [ ] `압구정 스테이크`
- [ ] `서래마을 레스토랑`
- [ ] `콜키지 와인바`
- [ ] `콜키지 프리 레스토랑`
- [ ] `코르키지 레스토랑`
- [ ] `와인 반입 가능 레스토랑`

### 각 검색어마다 볼 것

- [ ] 상위 결과가 실제 식당인가
- [ ] 식당 외 업종이 많이 섞이는가
- [ ] 지역 의도가 잘 반영되는가
- [ ] `콜키지` 키워드가 실질적으로 도움이 되는가
- [ ] 같은 식당이 중복으로 많이 보이는가

## 3. 응답 필드 검증

각 응답에서 아래를 확인합니다.

- [ ] `title` 존재
- [ ] `title`에 HTML 태그 포함 여부 확인
- [ ] `category` 존재
- [ ] `description` 존재 여부 확인
- [ ] `address` 존재
- [ ] `roadAddress` 존재
- [ ] `mapx` 존재
- [ ] `mapy` 존재
- [ ] `link` 값 품질 확인
- [ ] `telephone`가 실제로 비어 있는지 확인

### 판단 포인트

- [ ] `title` 정제 로직이 필요해 보이는가
- [ ] `category`만으로 업종 필터가 어느 정도 가능한가
- [ ] 주소 정보가 비어 있는 경우가 있는가
- [ ] 좌표가 바로 지도 표시에 쓸 만한가
- [ ] 상세 API 없이도 내부 상세 화면 초안에 필요한 최소 정보가 확보되는가
- [ ] `link`가 비어 있거나 외부 URL이 섞이는 점을 감안해도 안정적 참조값으로 쓸 수 있는가
- [ ] `telephone` 공란이 계속 유지되는가

## 4. 파라미터 동작 확인

문서 설명에 일부 불일치가 있어 실제 테스트가 필요합니다.

### display

- [ ] `display=1` 확인
- [ ] `display=5` 확인
- [ ] `display=10` 확인
- [ ] 허용 범위 실제 판정 기록
- [ ] `display=10` 요청 시 실제 응답이 `display=5`로 보정되는지 확인

### start

- [ ] `start=1` 확인
- [ ] `start=2` 또는 다음 페이지 성격 확인
- [ ] 허용 범위 실제 판정 기록
- [ ] `start=2` 요청 시 실제 응답이 `start=1`로 보정되는지 확인

### sort

- [ ] `sort=random` 확인
- [ ] `sort=comment` 확인
- [ ] 어떤 정렬이 후보 수집에 더 유리한지 기록

## 5. 노이즈와 한계 확인

- [ ] 광고성/비관련 결과가 많은가
- [ ] 식당인데 카테고리가 애매한 경우가 많은가
- [ ] `콜키지` 키워드가 거의 무의미한가
- [ ] 원하는 식당이 빠지는 경우가 많은가
- [ ] 전화번호 필드는 사실상 비어 있는가
