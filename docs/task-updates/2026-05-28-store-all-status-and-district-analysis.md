- 이번 수정으로 지역 선택 후에는 콜키지 여부와 관계없이 해당 지역의 모든 식당을 보여준다.

## 지역을 나누는 기준

현재 지역 목록은 DB의 `stores.district` 컬럼 그대로 만든다.

- 화면의 지역 select: `listCanonicalDistricts()` → `listDistrictsFromDatabase()`
- DB 조회: `readCanonicalStores({ status: 'all', district })`
- 필터 기준: `stores.district = 선택한 district` exact match

`district` 값은 import 시점에 만들어진다.

1. `PlaceListBusinessesItem` 소스
   - `node.commonAddress`가 있으면 우선 사용
   - 없으면 주소에서 `inferDistrict(address)`로 추론
2. `InformationFacilities` 배열 소스
   - 주소에서 `inferDistrict(address)`로 추론

`inferDistrict(address)` 기준:

- 주소를 공백으로 쪼갠다.
- 첫 행정 단위로 `[시도]`로 끝나는 토큰을 넣는다.
- 뒤이어 `[시군구]`로 끝나는 토큰을 계속 넣는다.
- 그 다음 토큰이 `[읍면]`으로 끝나거나, 길이 4 이하의 `[동]`이면 넣는다.
- 그 외 토큰이 나오면 바로 중단한다.

## 동탄구가 동까지 못 내려가는 이유

동탄구로만 묶인 20개는 대부분 주소가 아래처럼 도로명 주소 구조다.

- `경기도 화성시 동탄구 동탄대로시범길 134 ...`
- `경기도 화성시 동탄구 동탄대로 446 ...`

이 경우 `inferDistrict`는 다음 순서로 처리한다.

1. `경기도` → 시도 인정
2. `화성시` → 시 인정
3. `동탄구` → 구 인정
4. 다음 토큰 `동탄대로시범길` 또는 `동탄대로` → 읍/면/동이 아님
5. 여기서 중단
6. 결과가 `경기도 화성시 동탄구`가 됨

즉, 동을 못 찾는 원인은 코드가 틀렸다기보다 현재 DB에 들어온 주소가 지번 주소가 아니라 도로명 주소 위주라서 동 토큰이 바로 나오지 않기 때문이다.

예외도 있다.

- `스타벅스 동탄카림점` 주소에는 `(청계동, ...)` 힌트가 뒤에 있지만, 현재 추론 로직은 괄호 안 동명까지 뒤져보지 않는다.
