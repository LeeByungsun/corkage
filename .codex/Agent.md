# Corkage Project Agent Guide

## 목적

이 프로젝트는 `콜키지 가능한 식당을 지도 기반으로 탐색하는 웹 서비스`를 만들기 위한 저장소입니다.

현재 최우선 목표는 구현이 아닙니다.

1. 네이버 지도 / 네이버 API로 어디까지 가능한지 검증
2. `콜키지 가능 여부` 데이터를 어떻게 확보할지 결정
3. MVP 범위를 작은 단위로 자르기

## 현재 단계에서의 기본 태도

- 바로 앱부터 만들지 않는다.
- 먼저 공식 문서와 실제 테스트로 가능 범위를 확인한다.
- 네이버 API가 해결하는 문제와 자체 데이터가 필요한 문제를 분리한다.
- 모든 결정은 짧은 문서로 남긴다.

## 핵심 판단 기준

이 프로젝트는 아래 2축으로 나눠서 봐야 한다.

### 1. 지도/위치 축

네이버 지도, 좌표 변환, 지역 검색, 마커 표시.

### 2. 콜키지 데이터 축

콜키지 가능 여부, 비용, 조건, 최신 확인일, 출처.

중요한 점:

- 지도 축은 네이버 API로 상당 부분 해결 가능성이 높다.
- 콜키지 데이터 축은 별도 저장과 검수 정책이 필요할 가능성이 높다.

## 현재 권장 에이전트

우선 사용:

- `researcher`  : 공식 문서, 정책, 인증 방식, 호출 조건 확인
- `architect`   : 데이터 흐름, 브라우저/서버 경계, MVP 구조 설계
- `planner`     : 테스트 순서와 산출물 정리
- `designer`    : 지도 탐색 UX, 리스트/상세 구조 정리
- `verifier`    : API 가능 여부와 테스트 결과 판정
- `writer`      : 결정사항 문서화

구현 단계 이후:

- `executor`
- `debugger`
- `test-engineer`
- `code-reviewer`

## 현재 권장 스킬

보조:

## 작업 순서

1. 네이버 API 후보와 인증 방식을 정리한다.
2. 브라우저 직접 호출과 서버 경유 호출 경계를 정한다.
3. 콜키지 데이터 필드를 정한다.
4. MVP 화면 수를 줄인다.
5. 그 다음에만 실제 앱 초기화와 구현으로 넘어간다.

## 완료 기준

구현 시작 전 아래가 정리되어 있어야 한다.

- 어떤 네이버 API를 쓸지 확정됨
- 어떤 데이터는 네이버에서 오고 어떤 데이터는 직접 관리하는지 정리됨
- MVP 지역 범위가 정해짐
- MVP 필터와 상세 필드가 정해짐
- 데이터 최신성 표기 정책이 정해짐
